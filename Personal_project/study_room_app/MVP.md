# 공부방 출결·정산 앱 MVP 기능 정의서

**버전**: 0.1 (초안)
**작성일**: 2026.04.18
**문서 목적**: 제품 개발 착수 전, 기능 범위와 제외 항목을 명확히 하여 범위 확장(feature creep)을 방지

-----

## 1. 제품 개요

### 1.1 한 줄 정의

공부방·1인 교습소 원장을 위한, **등하원 알림과 수강료 정산만 제대로 하는** 앱.

### 1.2 타겟 고객 (ICP, Ideal Customer Profile)

- 운영자: 공부방·1인 교습소 **원장 1인**이 운영 전반 책임
- 학생 규모: **5~30명** (30명 초과 시 학원용 솔루션이 더 적합)
- 과목: 영어·수학·논술 (MVP는 영어 또는 수학 중 **한 과목 특화 출시** 권장)
- 현재 도구: Excel + 카카오톡 단톡방 + 네이버밴드 조합
- 월 결제 수용 가능 금액: 1~3만원

### 1.3 핵심 가치 제안

- 원장: 매주 2~3시간 걸리던 출결 정리·수강료 계산 → **10분 이내**
- 학부모: 자녀 등원/하원 **실시간 알림**으로 불안 해소
- 학생: 별도 앱 사용 부담 없음

### 1.4 MVP 성공 정의 (6개월 시점)

- 유료 전환 고객 **30곳** 확보
- 월 재계약률 **90% 이상**
- 원장 NPS **30점 이상**

-----

## 2. 페르소나

### 2.1 원장 김선생 (Primary — 구매 및 운영 주체)

- 40대 초반 여성, 초등 영어 공부방 5년차
- 학생 22명, 주 5일 운영
- 매주 일요일 저녁 2시간씩 출결/수강료 정리
- Pain: "결석 처리 헷갈려서 학부모랑 돈 문제로 얼굴 붉힌 적 있음"
- 결제 권한: 본인 (의사결정 즉시)

### 2.2 학부모 이엄마 (Secondary — 알림 수신자)

- 30대 후반, 맞벌이
- 자녀 등하원을 직접 확인 못 함
- Pain: "아이가 공부방 잘 도착했는지, 언제 나왔는지 모름"
- 앱 설치 의향: **낮음**. 카카오 알림톡으로 충분.

### 2.3 학생 박초딩 (Tertiary — 사용자 아님)

- 초등 3~6학년
- 개인 휴대폰 **없는 경우 다수**
- → MVP는 학생폰에 의존하지 않는 설계 필수

## 3. 핵심 유저 시나리오

### 3.1 등원 (매일 반복)

1. 학생이 공부방 도착
1. 원장이 태블릿/폰에서 학생 이름 **원터치 체크인**
1. 시스템이 해당 학생 학부모에게 알림톡 자동 발송
- "○○이 4:02분에 도착했습니다"

### 3.2 하원 (매일 반복)

1. 수업 종료, 학생 귀가
1. 원장이 **원터치 체크아웃** (또는 수업 종료 시 일괄 처리)
1. 학부모 알림톡 자동 발송
- "○○이 6:03분에 하원했습니다"

### 3.3 결석 처리

1. 학생 미등원 시 원장이 **결석 사유 선택** (개인사정/병결/통보없음)
1. 학부모에게 자동 알림
1. 결석 기록은 월말 정산에 **차감 규칙대로 자동 반영**

### 3.4 월말 정산 (월 1회)

1. 원장이 "이번 달 정산서 생성" 버튼 클릭
1. 학생별 수강료 자동 계산
- 기본 수강료 − 결석 차감 + 보강 차감 − 형제 할인
1. 학부모별 납부 안내 알림톡 일괄 발송
1. 수납 완료 체크 (현금/계좌이체 수동, 카드결제는 Phase 2)

### 3.5 신규 학생 등록

1. 원장이 학생 정보 입력 (이름, 학년, 반, 학부모 연락처, 수강료)
1. 학부모에게 등록 완료 알림톡
1. 다음 수업일부터 출결 체크 대상에 포함

## 4. 기능 명세

### 4.1 Must Have — MVP 필수 (0~3개월 개발)

#### A. 학생·반 관리

- 학생 등록/수정/삭제 (이름, 학년, 학부모 연락처, 반, 수강료)
- 반(클래스) 생성 및 학생 배정
- 요일별 수업 시간표 설정

#### B. 등하원 기록

- 원장 앱에서 **원터치 체크인/체크아웃**
- 반별 일괄 체크인 (수업 시작 시 출석 확인)
- 결석 사유 선택형 입력 (개인사정 / 병결 / 통보없음 / 기타)
- 과거 기록 조회 및 수정 (최근 30일)

#### C. 자동 알림 (카카오 알림톡)

- 등원 알림
- 하원 알림
- 결석 알림
- 월말 수강료 납부 안내
- **학부모 앱 설치 불필요** — 알림톡만으로 동작

#### D. 수강료 정산

- 학생별 월 수강료 설정
- 결석 차감 규칙 설정 (예: 월 2회까지 차감 없음, 이후 회당 차감)
- 형제 할인 규칙 설정
- 월말 정산서 자동 생성
- 수납 여부 수동 체크 (입금 확인)
- 정산 내역 PDF/이미지 내보내기

#### E. 원장 대시보드

- 오늘의 출결 현황 (등원/결석/하원 대기)
- 이번 달 예상 매출 / 미수금
- 학생별 출석률

### 4.2 Should Have — Fast Follow (4~6개월)

- 카드 결제 연동 (토스페이먼츠 정기결제)
- 월중 등록 시 **일할 계산**
- 보강 일정 관리
- 학부모 알림톡 → 앱 가벼운 버전 (등하원 히스토리 조회용)
- 현금영수증 연동
- 원장 간 데이터 이관 (기존 엑셀 CSV 임포트)

### 4.3 Won't Have — MVP 의도적 제외

**원칙**: 클래스팅·알리미와 싸우는 순간 포지션이 흐려진다. "출결+정산 특화"를 지킨다.

| 제외 기능         | 제외 이유                                   |
| ----------------- | ------------------------------------------- |
| 숙제 관리         | 클래스팅 영역. 들어가면 포지션 흐려짐       |
| 성적/시험 관리    | 학원 솔루션 영역. 공부방 원장 실제 니즈 낮음 |
| 상담일지          | 사용 빈도 낮고 유료 전환 기여도 미미        |
| 커리큘럼/수업자료 | 원장마다 방식이 달라 표준화 어려움          |
| 학부모 채팅       | 카카오톡 존재. 중복 가치 없음               |
| 차량(픽업) 관리   | 공부방은 대부분 차량 미운영                 |
| 학생용 앱         | 초등학생 다수가 개인폰 없음                 |

## 5. 화면 구조 (Screen Map)

### 5.1 원장 앱 (iOS + Android, Primary 개발)

- **오늘** (홈): 오늘의 출결 현황 + 퀵액션
- **학생**: 학생 목록, 등록, 수정
- **반**: 반 관리, 시간표
- **출결**: 날짜별/학생별 기록 조회·수정
- **정산**: 월별 정산서, 미수금 관리
- **설정**: 결석 차감 규칙, 형제 할인, 알림 문구

### 5.2 학부모 (MVP는 앱 없음)

- 카카오 알림톡 수신만
- Phase 2에서 웹 기반 경량 뷰 (히스토리 조회)

## 6. 등하원 감지 방식 — 기술 의사결정

| 방식                | 장점                                     | 단점                         | MVP 적합성 |
| ------------------- | ---------------------------------------- | ---------------------------- | ---------- |
| 원장 수동 체크 (권장) | 구현 단순, 하드웨어 불필요, 즉시 출시    | 원장 수고                    | ★★★★★      |
| QR 태깅             | 자동화 느낌                              | 학생 스마트폰 필요           | ★★         |
| BLE 비콘            | 완전 자동                                | 학생폰·비콘·배터리 이슈      | ★          |
| NFC 카드            | 직관적                                   | 리더기 하드웨어 필요         | ★          |
| 얼굴인식 키오스크   | 최고 UX                                  | 고가, 개인정보 이슈          | ☆          |

**MVP 결정**: 원장이 태블릿/폰에서 **원터치 체크**. Phase 2에서 반 단위 QR 또는 학생카드 옵션 추가.

이유: 공부방은 학생 수가 적어 원장이 누가 왔는지 직접 인지함. "자동화"보다 "1분 내 끝나는 단순함"이 진짜 가치.

## 7. 기술 스택 제안

- **프론트엔드**: React Native (iOS+Android 동시 대응)
- **백엔드**: 근태 앱 자산 재활용 — 인증·조직관리·출결기록 로직 60~70% 재사용 가능
- **DB**: PostgreSQL
- **알림톡**: 카카오 비즈메시지 공식 파트너사 (알리고, NHN토스트 등)
- **결제 (Phase 2)**: 토스페이먼츠 정기결제
- **분석**: Amplitude 또는 Mixpanel

## 8. 출시 기준 (Release Criteria)

### 8.1 베타 출시 기준 (2~3개월차)

- Must Have 기능 A~E 전체 동작
- 알림톡 발송 성공률 99%+
- 원장 1명이 "엑셀 없이 한 달 운영 가능" 수준

### 8.2 정식 출시 기준 (3~4개월차)

- 베타 고객 10곳 중 **7곳 이상이 유료 전환 의향**
- Crash Free Rate 99.5%+
- 온보딩 완료율 70%+ (등록 → 학생 5명 입력까지)

## 11. 리스크 및 가정

### 11.1 주요 가정

- 공부방 원장이 **월 1~3만원 결제 의향 있다** → 사전 인터뷰 10명 검증 필요
- 학부모는 **앱 설치 없이 알림톡만으로 만족한다** → 베타에서 검증
- 카카오 알림톡 **발송 단가(건당 8~15원)**가 단위 경제성 해치지 않는다 → 학생당 월 알림 40건 기준, 단가 원가 반영 필요

### 11.2 핵심 리스크

- **리스크 1**: 알리미가 공부방 시장 진입 → 대응: 속도. 6개월 내 30곳 확보로 레퍼런스 선점
- **리스크 2**: 카카오 알림톡 정책 변경 → 대응: SMS 백업 채널 설계
- **리스크 3**: 원장이 "엑셀이 더 편하다"며 이탈 → 대응: 엑셀 CSV 임포트 1분 이내 완료 보장
